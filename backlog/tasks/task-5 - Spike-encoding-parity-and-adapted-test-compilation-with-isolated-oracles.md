## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Prove the riskiest end-to-end assumptions before the full port. Use TASK-4's selected I/O approach, the build runner from TASK-2 and conventions from TASK-3. Translate a bounded reader/writer slice and compile representative upstream runtime and parser-model Kotlin test cases against Java implementations. Cover named-argument adaptations and fixture generation, not just empty module compilation. Run upstream Wire in a separate process/classpath. Capture representative Apicurio schema-operation outputs using upstream 6.4.0 and 7.1.0 as later integration baselines; this does not require an unbuilt ported schema loader or changes to Apicurio production code.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The chosen encoding slice produces bytes matching upstream Wire 7.1.0 for an enumerated representative proto2/proto3 corpus, including varints, tags, groups, packed fields and malformed lengths.
- [ ] #2 At least one relevant runtime test and one parser-model test from the pinned upstream sources compile and execute against the Java slice with mapped adaptations and preserved inputs, expectations and exception behavior.
- [ ] #3 A fixture generated by the pinned upstream build-time tool compiles and executes against the Java slice, or an equivalent reviewed adaptation is demonstrated; unsupported fixture call forms are inventoried rather than hidden.
- [ ] #4 The verification entry point proves upstream implementation jars cannot satisfy port test calls and records actual loaded-class origins and the tag/commit of each reference run.
- [ ] #5 A reproducible bounded Apicurio schema-operation corpus records upstream 6.4.0 versus 7.1.0 results, and M0 evidence records translation effort, remaining uncertainty and the resulting go/no-go decision before M1.
- [ ] #6 Executable reference-versus-port examples exercise nullable and non-null boundaries, null-check placement, require throwing IllegalArgumentException and checkNotNull throwing IllegalStateException. The shared verification entry point runs them and detects changed exception or null behavior.
- [ ] #7 The finalized I/O and publication grouping from TASK-4 is validated with an actual Java 11 consumer of the Java spike and its resolved production dependencies. Remaining runtime/schema/generator release checks stay explicitly pending until their implementation.
