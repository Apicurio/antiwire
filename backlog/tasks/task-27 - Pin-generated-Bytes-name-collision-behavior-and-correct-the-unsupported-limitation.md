## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The original 2026-10-03 review alleged that a message or enum named Bytes causes generated runtime-byte imports to shadow user types and break compilation. The 2026-10-06 audit at 295ef5f0e7a1e45937417b9f621044d8139df6f5 refuted that concrete premise for tested top-level proto3 shapes. Independent generator runs covered same-package and cross-package message Bytes, a Bytes message containing its own bytes field, a sibling referencing only the message, repeated bytes, map<string,bytes>, repeated message values, and an enum named Bytes. Generated code qualifies conflicting type names, compilation succeeds, and a mixed message round-trip preserves field and adapter types.

Keep this existing task open for regression coverage and correction of the unsupported limitation in docs/api-surface.md and docs/compatibility-matrix.md. Do not implement the original proposed qualification workaround without a failing generated-source example. Nested types, proto2, oneof and extension variants remain unverified. Collisions with other imported names are also unverified, not confirmed defects, and need no speculative rewrite. This task supersedes the original review premise without claiming that all possible collision shapes are proven safe.
